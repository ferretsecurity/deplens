VERS change review helper

A layered review map for the normalized range field. Read the change as a sequence of contracts: output shape, enrichment point, parser adaptation, then evidence.

01

Public API: additive and quiet

Start here. This layer decides whether consumers see a breaking schema change. It should be an optional, derived field with no effect on existing raw, version, or constraint values.

type Dependency struct {
  Type       PackageType       `json:"type,omitempty"`
  Raw        string            `json:"raw"`
  Name       string            `json:"name,omitempty"`
  Version    string            `json:"version,omitempty"`
  Constraint string            `json:"constraint,omitempty"`
  VERS       string            `json:"vers,omitempty"`
  Section    string            `json:"section,omitempty"`
}

Review question: Does the uppercase Go field name satisfy internal naming intent while the lower-case JSON key remain consistent with the existing schema?

Accept if

  • vers is omitted when empty.
  • constraint is never rewritten.
  • Resolved versions alone do not produce VERS.
  • Golden JSON exposes the addition.

Why here: a requirement parser can identify >=2.31, but only the ruleset establishes that it is PyPI rather than npm-like syntax.

Boundary checks

  • No change to selector-only or presence-only detectors.
  • Custom rules with known package types participate automatically.
  • Parser-provided types remain untouched by the rule.
  • Dependency order is preserved.
03

Parser adapter: native syntax in, portable range out

The adapter chooses a VERS-native parser scheme from the PURL type, parses the source constraint, and asks that library to serialize the resulting canonical URI.

No constraint
constraint == ""
Return empty. A lockfile’s resolved version must not become an inferred range.
Known ecosystem
pypi · golang · npm · maven · gem · cargo
Select the matching native scheme, then emit the VERS URI with the same scheme.
Unsupported type
default
Return empty: no invented semantics and no scan warning.
Parse failure
err != nil
Return empty: keep the original constraint visible for consumers that understand it.
func dependencyVERS(packageType PackageType, constraint string) string {
  nativeScheme, outputScheme, ok := versSchemeForPackageType(packageType)
  if !ok || constraint == "" { return "" }

  parsed, err := vers.ParseNative(constraint, nativeScheme)
  if err != nil {
    // Preserve the source constraint; do not fail the scan.
    return ""
  }
  return vers.ToVersString(parsed, outputScheme)
}

Key review point: Unknown package types, including Composer, return an empty VERS field rather than borrowing another ecosystem’s syntax.

Risk-focused review

Look closely: every emitted URI comes from the VERS library; do not translate an intermediary parser representation locally.

Expected: >=2.31 becomes vers:pypi/>=2.31.
